# 问题与约束

说明为什么必须新增一个组件，以及该组件被哪些条件限制。设计与部署见 [02-design.md](02-design.md)、[03-deployment.md](03-deployment.md)。

## 1. 问题

看板能回答“谁在用、用了多少”，但不能回答“问了什么、答了什么”。合规检查、事故回溯、滥用排查都缺这一层。

根因不在看板：New API 在转发过程中确实接触明文请求与响应，但**从不把它们写入任何可查询的存储**。

## 2. New API 的日志能力核验

核验对象：v1.0.0-rc.23 部署实例、`logs` 表实测结构（见 [../db-schema-notes.md](../db-schema-notes.md) §3.2）。

| 字段 | 实际内容 | 能否承载提示词 |
|---|---|---|
| `logs.content` | 计费说明、模型映射、错误文本（`[]*common.Message` 拼接的英文串） | 否 |
| `logs.other` | JSON 元数据，按 `public` / `admin_info` / `root_info` / `audit_info` 投影 | 结构上可以，但当前无写入方 |
| `logs.request_id` / `upstream_request_id` | 请求标识 | 否，仅可作关联键 |
| `logs.prompt_tokens` / `completion_tokens` | 计量值 | 否 |

`other.admin_info` 是“仅管理员可见”的既有机制（`reject_reason` 即走此路径），说明**权限模型已具备**，缺的是写入逻辑。

## 3. 运行时扩展点核验

评估结论：rc.23 不存在任何可供第三方插入请求链路的机制。

| 扩展点 | 结论 | 依据 |
|---|---|---|
| Go 插件（`.so` 动态加载） | 不可用 | 只有 `init()` 编译期注册，无运行时加载入口 |
| 任务插件（rc.50 前后引入的插件体系） | 不适用 | 仅覆盖图片/视频/音乐任务型上游；沙箱禁止 `import`、`require`、`fetch`、`fs`、`env`、`async`，插件无法对外投递数据 |
| 请求处理插件（同期引入） | 不适用 | 公开文档未提供开发接口；已落地实例是“请求过滤”（敏感词迁移而来），只做拦截，无外部 IO |
| 日志外置（`LOG_SQL_DSN` → ClickHouse） | 无收益 | 外置的仍是元数据，提示词从未进入日志模型 |
| 系统设置项 | 不存在 | 文档站与配置项均无“记录请求内容”开关 |

上游同诉求 issue（[QuantumNous/new-api#7609](https://github.com/QuantumNous/new-api/issues/7609)）截至归档时无维护者回应、无 PR。因此不能以“等官方支持”作为交付前提。

推论：**凡需要重新编译才能加入的逻辑都是补丁，不是扩展**。要获得“升级免改”的能力，采集点只能落在进程之外。

## 4. 结构约束

这些约束直接决定了后续设计形态，不可绕过。

| 约束 | 内容 | 设计影响 |
|---|---|---|
| 响应流只能读一次 | 请求可复制，响应不可；`nginx mirror` 只复制请求 | 要采集返回内容，必须有组件在转发路径上 |
| 只读数据库 | 看板使用只读账号，类型层不暴露写入口，会话强制 `default_transaction_read_only=on` | 采集产物不能写 PostgreSQL，只能落文件 |
| 不修改 New API | 不写 schema、不改源码、不重建镜像 | 采集逻辑不能依赖 New API 的任何改动 |
| 部署形态 | New API 为 Docker 部署，前置 nginx 反向代理 | 采集器可作为容器或裸机进程插入 |
| nginx 版本 | 1.30.4，编译含 `lua-nginx-module 0.10.29` 与 `ngx_devel_kit 0.3.4` | Lua 方案技术上可行，但存在阻塞与压缩两个硬伤，见 [04-decisions.md](04-decisions.md) D3 |
| 请求规模 | 约 5.6k 请求/天（近 97 天 545k 行） | 单机文件方案足够，无需分布式存储 |
| 上下文规模 | 单请求可达 1M tokens（约 4–5 MB 原始 JSON） | 采集实现必须与 body 大小解耦，不能整体读入内存 |

## 5. 成功判据

| 判据 | 目标 |
|---|---|
| 升级 New API | 采集链路无需改动、无需重新编译 |
| 采集失败 | 不影响 LLM 调用；最坏情况只丢采集 |
| 内存 | 与单请求 body 大小无关 |
| 数据位置 | 不写入业务库，不触碰只读红线 |
| 追溯粒度 | 单次请求可定位到具体 trace，并能关联到 New API `logs` 行 |
