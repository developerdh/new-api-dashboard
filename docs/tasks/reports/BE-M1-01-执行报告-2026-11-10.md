## 3. 关键结论

1. **无时区 ISO 一律按 Asia/Shanghai 解释**：`2026-11-10` → 东八区 00:00（`1794240000`），不跟随运行环境时区；带 `Z`/`+08:00` 的字符串按原时区解析。避免服务器部署在 UTC 时口径漂移。
2. **周起点 = 周一**：与 PG `DATE_TRUNC('week', …)` 对齐（周日 vs 周一错位会直接影响周趋势桶）。日历运算用 `Intl.DateTimeFormat` + 迭代修正偏移，未引入 luxon。
3. **key 确定性**：ISO 与 Unix 输入先归一为整数秒再进 `cacheKey`，同语义参数（含 URLSearchParams 入口）必然同 key；单测直接比对完整 key 字符串。
4. **`meta.cached` 的实现**：`cachedQuery` 先 `has()` 探测再走 `getOrCache`，返回 `{ data, cached }`，不修改缓存层（BE-M0-04 零改动）。
5. **Zod v4 flatten 的类型坑**：`z.flattenError(error)` 在 `z.ZodError`（默认 `T = unknown`）下推导出 `fieldErrors: {}`，`Object.entries` 后 values 不可迭代；改为泛型参数 + `Record<string, string[] | undefined>` 收窄。
6. **白名单重复定义**：`MODEL_NAME_PATTERN` 与 `cache.ts` 的 key 校验同规则、两处定义（缓存层不允许把非法串拼进 key，查询层要返回 400 issues）；已各自单测锁定，规则变更需同步。
