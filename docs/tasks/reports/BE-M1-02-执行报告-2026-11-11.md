## 3. SQL 口径（`compile()` 断言）

- quota_data：`COALESCE(SUM(quota|token_used|prompt_tokens|completion_tokens), 0)::bigint`、`COUNT(DISTINCT user_id|model_name)::bigint`；
- logs：`COUNT(*)::bigint`；
- 区间条件 `"created_at" >= $1 and "created_at" < $2`（左闭右开），参数以 `$1/$2` 下发，SQL 文本中不含具体时间戳。
- 数值统一 `::bigint`：避免 PG `SUM(bigint)` 返回 numeric 被 node-postgres 解析成 string（notes §5.3）。

## 4. 关键结论

1. **缺省策略**：`start`/`end` 都缺省 → 今日（Asia/Shanghai）00:00 至次日 00:00；只给一个 → 400 缺参，不做「半默认」区间（避免前端漏参得到意外口径）。
2. **缓存 key 只含区间**：总览无粒度/用户/模型维度，`granularity`/`userId`/`modelName`/`limit` 不参与 key，避免同区间多 key 白占内存；参数仍会校验并回显在 `meta.granularity`。
3. **`meta.source=quota_data+logs`**：总览混用两个来源（quota_data 最多 5 分钟延迟，请求数走 logs），在响应里显式标注，前端可决定是否提示口径差。
4. **空区间全 0**：聚合行缺失时 `toOverviewSnapshot(undefined, undefined)` 返回全 0（逐字段 `Number.isFinite` 兜底），不会出现 null/NaN。
5. **无库验证路径**：SQL 用 `compile()` 锁定、执行层用 mock 单测、HTTP 用生产 e2e 覆盖错误分支；成功路径的真实数值只能待真实/demo 库（LH-05）。
