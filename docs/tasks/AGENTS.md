# AGENTS.md — 任务管理机制（docs/tasks/）

本文件定义本目录任务体系的运行逻辑，在本目录工作时自动加载，无需额外引用。
与仓库根说明文件分层：根 `AGENTS.md` 管仓库级规范（git/环境/架构约束），本文件只管任务机制。
职责边界：**看板与各记录文档只记任务状态与事实；本文件只写机制规则。**

## 记录纪律（最高优先，适用于本目录全部文档）

1. **只记录与文档职责有关的内容**。上下文噪声、决策噪声一律不入任何任务文档。
2. **任务相关决策信息（允许记录）**：影响实现/验收/后续口径的**结论**——口径定稿、方案选型结果、验收判据、遗留事项。落点=任务卡「关键口径摘要」「变更记录」（一行结论）+ 权威文档回流。
3. **任务无关决策噪声（禁止记录）**：决策过程叙事——谁在何时拍板、批复对话、复测反馈流水、批准用语、时间线回顾、「用户指示…」类表述。
4. **判别准则**：后续任务推进是否需要这条信息。需要→结论落机制位；不需要→只进执行报告或丢弃。
5. **体量信号**：单行/单元格超过约 500 字符即视为噪声信号，必须重写为一行式或拆分归属。
6. **机制载体只写本项目实际生效的规则**：不写差异对照、定制注记、初始化记录等生成过程信息——定制体现在各文档的实际内容中（名称/编号/路径直接写实际值）。

## 文档职责与信息流

| 文档 | 职责（每份只做一件事） |
|---|---|
| `README.md` | 看板：当前指针、在办任务表、开放遗留表、权威文档清单 |
| `_template.md` | 任务卡骨架与收尾 checklist |
| `FEEDBACK.md` | 用户 BUG/需求反馈唯一入口；转任务后删除对应行 |
| `BACKLOG.md` | 待排期与取消项登记 |
| `COMPLETED.md` | 已完成任务一行式索引（滚动归档，见下） |
| `m0/`–`m4/` 任务卡 | 单任务全部事实：口径摘要/起点基线/阶段/验收/续作区（状态唯一事实源）/变更记录 |
| `leftover/` | 复杂遗留立卡（LO-编号） |
| `reports/` | 任务执行报告（终点归档） |
| `archive/` | 归档域：已完成任务卡、历史台账快照、完成索引归档段 |
| `validate-tasks.mjs` | 只读一致性校验 |

信息流主链：`FEEDBACK`（用户指示转出）或 `BACKLOG`（进入排期）→ 按 `_template.md` 建卡 → 检查点推进 → 收尾 checklist → 执行报告 + 卡片归档 + 完成索引登记 → 看板指针推进。

FEEDBACK 三分支（均由用户明确指示触发，转出后删除对应行，本文件不留已确认事项）：
1. 转任务卡（常见路径，BUG 类快进快出）→ 看板在办表；卡「变更记录」首行注明来源 F-编号。
2. 转 `BACKLOG.md` 待排期节（认可要做但不排期的需求），说明列只写事项本身。
3. 核实不成立/决定不做 → 直接删行；曾规划后取消的事项进 BACKLOG 取消节留原因。

判别线：BACKLOG 只收已确认的需求/功能事项，**不收 BUG**——BUG 要么转卡修，要么删；长期挂起的 BUG 应转任务卡或遗留项管理。

## 编号族

- 任务：`<ROLE>-M<里程碑>-<序号>`，ROLE ∈ BE（服务端/数据）/ FE（前端）/ INF（脚手架/部署/基建），里程碑 M0–M4，序号两位递增（如 `BE-M1-02`、`FE-M2-05`、`INF-M0-01`）。
- 反馈条目 `F-<nnn>`；看板遗留项 `LH-<nn>`；遗留任务卡 `LO-<nn>`。
- 执行报告：`<编号>-执行报告-<YYYY-MM-DD>.md`（`reports/` 内，编号即定位）。
- 编号如有弃用空洞，在此处载明并不再补用：暂无。

## 检查点制

任务文档只在三个时刻更新：开始（续作区置 `in_progress`）、中断（续作区写 1–2 行断点备注）、完成（收尾 checklist）。推进过程中不更新任何任务文档。
断点备注**覆盖式更新**：只保留当前断点，旧断点收敛成变更记录一行，不堆叠时间线。
状态唯一事实源 = 任务卡「续作区」；看板在办表状态列与卡头部状态行必须与其一致（校验 ERROR 级保障）。

## 会话接力

- 新会话：看板指针 → 打开 current 卡读「关键口径摘要 + 续作区」→ 按 `_template.md` 的章节结构生成开场提示词后开工。
- 开场提示词**在对话中生成，不预写进任务卡**，要素：必读路径 / 目标 / 整改项 / 承接点与风险 / 环境约束（引根 `AGENTS.md`）/ 执行要求 / 红线。
- 收尾会话义务：按指针与卡内前置关系推荐下一任务，并在对话中输出其开场提示词。

## 遗留处理机制

- **双向登记**：新增遗留 = 来源任务卡变更记录 + 看板遗留表（LH 编号）各一行；闭环 = 看板**删行** + 处理方任务卡/完成报告留结论（closed 行不留看板）。
- **立卡门槛**：需独立推进的复杂遗留，在 `leftover/` 立卡（`LO-<序号>`，结构按 `_template.md`）；简单遗留直接在看板遗留表登记与闭环。遗留卡闭环：移入 `archive/leftover/` + 完成索引登记 + 看板删行。
- **历史不设常设台账**：闭环事实只留处理方；重大机制调整时对存量做一次性快照（`archive/历史台账-<日期>.md`），归档域规则适用。

## 回流规则

本项目唯一外部权威定稿为 `docs/方案.md`（红线：不可修改）。改动权威文档前：整理《回流修改说明》（改动点/原因/回滚方式）→ 用户批准 → 执行 → 结论按「记录纪律」落机制位；过程细节只进完成报告。未经批准不改。
项目内产出文档（如 `docs/db-schema-notes.md`）由对应任务卡自行维护，不属回流审批范围；若其结论与 `docs/方案.md` 口径冲突，冲突事实按遗留/回流处理。

## 归档域规则

- `archive/` 与 `reports/` 内文档**默认不读、不引用、不扫描**，仅用户明确指示时查阅。
- 在办文档不得出现指向归档内具体文档的引用。
- 归档定位不靠链接靠约定：任务卡在 `archive/<里程碑目录>/<编号>.md`（`m0/`–`m4/`），**编号即路径**。
- 执行报告命名 `<编号>-执行报告-<日期>.md`；报告为终点文档，其他任何文档不得引用它。

## 完成索引滚动归档

- `COMPLETED.md` 主文件只保留：① 在办批次相关的已完成行；② 「遗留」列仍活跃的行。
- 归档触发：某里程碑段全部任务完成、看板已无该批在办卡、该段遗留均已闭环 → 整段移入 `archive/COMPLETED-m<n>.md`，主文件删除该段。
- 校验器读取主文件+归档段编号并集做前置存在性校验（脚本读取≠文档引用）；主文件超 60 行输出 WARN 提示压缩。

## 红线

- git 提交等仓库级规范以指针引用根说明文件（`AGENTS.md`「Git 约定」节），本目录不复制正文。
- 不改 `docs/方案.md`（回流审批制，见上）。
- 归档域禁令（见上）。
- 敏感配置不入任何文档；路径引用一律项目根相对，禁本机绝对路径。

## 一致性校验

仓库根运行 `node docs/tasks/validate-tasks.mjs`（只读，无副作用）。ERROR（阻断）与 WARN（提示）分级见脚本头注；收尾要求 ERROR 清零，WARN 逐条知悉。
