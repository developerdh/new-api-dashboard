# BE-M3-03 · 服务端看板快照（POST /api/snapshot + Playwright）

> 里程碑：M3 · 导出与快照 ｜ 类型：新增 ｜ 预估：1 人日 ｜ 复杂度：M ｜ 状态：todo

## 目标
服务端用 Playwright 无头浏览器把看板任意页面（含时间范围参数）渲染为自包含静态 HTML 快照，归档 `public/snapshots/`；`POST /api/snapshot` 与 `scripts/snapshot.ts` CLI 双入口。

## 输入/必读文档
- [ ] `docs/方案.md` §8.2（Playwright 流程：goto→networkidle→content→写文件）、§8.3（快照内容建议）、§10（scripts/snapshot.ts）
- [ ] `src/app/api/admin/cache/*` 守卫模式（BE-M0-04 的 ADMIN_TOKEN 约定复用）、`/dashboard` 与 `/users/[id]` URL 参数口径（FE-M2-01），根 `AGENTS.md`（指针）

## 本任务关键口径摘要
- `POST /api/snapshot` body：`{ path: '/dashboard' | '/users/<id>' | '/models', query?: { start, end, granularity } , name?: string }`；`path` 白名单校验（防 SSRF 打内网任意地址，仅允许本站路由前缀）。
- 渲染流程按 §8.2：`chromium.launch()` → `goto(DASHBOARD_BASE_URL + path + '?' + query)` → `waitForLoadState('networkidle')` → `page.content()` → 写 `public/snapshots/<name>-<YYYYMMDD-HHmm>.html`；`browser.close()` 必须 finally 保证（防进程泄漏——本体系红线级实现点）。
- 并发控制：渲染队列同时=1（`Promise` 链式互斥），队列长度上限 3 超出 429。
- 守卫：`Authorization: Bearer ${ADMIN_TOKEN}`（同 BE-M0-04 模式，env 未配置则 404）。
- CLI：`pnpm snapshot --path=/dashboard --start=... --end=...`（scripts/snapshot.ts，tsx 运行），定时化只留接口不实现（BACKLOG 事项）。
- 依赖：新增 devDependency 不含、生产依赖加 `playwright` + `pnpm exec playwright install chromium`（Docker 镜像内安装步骤移交 INF-M4-01，登记看板遗留 LH 行）。
