## 本任务关键口径摘要
- 连接串唯一来源 `DATABASE_URL`（postgres://dashboard_readonly@…，优先从库）；连接池上限默认 10，env `DB_POOL_MAX` 可配 10–20，越界直接报错（方案 §2.1；红线不给放宽入口）。
- 建连超时 env `DB_CONNECT_TIMEOUT_MS` 默认 5000ms（100–60000），保证 `/api/health` 有界返回。
- 会话加固**双通道**下发，两者都作用于每条新连接：① 建连启动参数 `options`（`statement_timeout=30000` + `default_transaction_read_only=on`，服务端在建连阶段应用，原子无额外往返）；② 池级 `verify` 钩子再断言同一组 GUC，**失败即回传错误销毁连接**，不放行未加固会话（同时覆盖 pooler/中间件丢弃启动参数的场景）。语句超时固定 30s，不提供 env 放宽入口（方案 §9.2）。
- 只读守卫在类型层：`getDb()` 返回 `ReadOnlyDatabase = Omit<Kysely<Database>, 'insertInto'|'replaceInto'|'updateTable'|'deleteFrom'|'mergeInto'>`；写操作必须显式绕开 `getDb()` 另建实例。
- `src/server/schema.ts` 按方案 §2.2 **暂定**表结构：`quota_data`（user_id, username, model_name, created_at:int8, token_used, quota, prompt_tokens, completion_tokens）、`logs`（user_id, username, created_at:int8, model_name, quota, prompt_tokens, completion_tokens）、`users`（id, username, status, quota）；可空性暂按 NOT NULL。字段权威校准属 BE-M0-03，文件头已注记「以 docs/db-schema-notes.md 校准后为准」。
- `GET /api/health`：`{ ok, db: { status: 'up'|'down', latencyMs, error? } }`，成功 200 / 失败 503，响应头 `cache-control: no-store`；运维端点（方案 §4 契约之外的补充，不属契约变更）。探活上限 5000ms，任何失败（未配置/连不上/超时）收敛为 down 且**不抛异常**，错误信息经 `redactCredentials` 抹掉账号密码。
- 实例懒创建（未配置 `DATABASE_URL` 时只抛配置错误、不建池）并挂 `globalThis` 单例，防 Next dev 热重载多池；`destroyDb()` 供测试与优雅退出。
- `pg` 的 int8（OID 20）在模块加载时统一按 `Number` 解析（原风险项，结论见变更记录）。

## 风险/阻塞
- 生产从库连接信息属外部依赖：本卡未做真库连通验证（环境无 Docker/PostgreSQL），真实连通确认连同 200 判据移交 BE-M0-03。
- 会话加固依赖 pg-pool 的 `verify` 语义（新连接交付前调用、回传错误即销毁连接）：`@types/pg` 已声明该选项；若将来 pg 版本改动此语义，只读保证仍有启动参数 `options` 兜底。
- `default_transaction_read_only=on` 与启动参数 `options` 同受 pooler 影响；若目标环境为 pgbouncer 且丢弃启动参数，`verify` 钩子仍会逐连接补发 SET。
- int8 解析为 number：超过 2^53 的值会丢精度；本看板口径（quota/token 计数）不触及该量级，真库校准阶段一并复核。
