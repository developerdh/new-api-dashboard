## 本任务关键口径摘要
- 核验内容：information_schema/pg_indexes 查询三表实际列与索引；`SELECT MIN/MAX(to_timestamp(created_at)) FROM quota_data`（§2.3）得保留区间；logs 同样核验。
- 只读账号：`scripts/setup-readonly.sql` 落方案 §2.1 授权语句（本项目**不执行**，交 DBA/用户在目标库执行）；另加写权限收敛与角色级只读会话加固。
- 索引建议：`scripts/index-suggestions.sql` 落 `CREATE INDEX CONCURRENTLY` 清单；§2.4 实为 5 条（卡内「六条」为笔误），第 6 条 `idx_logs_model_created` 标注为补充建议。执行与否、落点（主库低峰/独立看板库；物理从库只读不能建索引）属用户侧运维决策。
- 与方案 §2.2 常见字段的**差异**（多列/缺列/类型不符）逐条记入 db-schema-notes.md；若差异影响 M1 统计口径（如 quota_data 无 model_name）→ 按回流规则出《回流说明》交用户决策。
- 验证路径（本卡实际执行）：环境无 psql/Docker/PostgreSQL 且按约束不安装 → 交付只读核验 SQL + 复验清单框架，结构事实标注「未对真实库复验」，真实库复验登记遗留 LH-04；`scripts/seed-demo.sql` 只交付不改判据（demo 库名闸门防误连）。
- schema.ts 校准策略：`Database` 仅保留 §2.2 基线列；未核验候选列隔离为 `*CandidateColumns` 不进 `Database`，由单测锁定，复验后按 notes §5.2 晋升。
