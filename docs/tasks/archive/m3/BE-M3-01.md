# BE-M3-01 · GET /api/export/csv 数据导出（限流）

> 里程碑：M3 · 导出与快照 ｜ 类型：新增 ｜ 预估：0.5 人日 ｜ 复杂度：S ｜ 状态：done

## 目标
`GET /api/export/csv` 支持 trend/users/models 数据集流式导出 CSV，参数口径与各 API 一致，带按端点限流。

## 输入/必读文档
- [ ] `docs/方案.md` §4（export/csv 接口）、§9.2（导出接口限流）、§5（各数据集 SQL 口径）
- [ ] `src/server/queries/common.ts`、`trend.ts`、`user.ts`、`model.ts`（既有查询复用）、根 `AGENTS.md`（指针）

## 本任务关键口径摘要
- 参数：`dataset=usersRanking|trend|modelsRanking|userModels` + 各数据集必要参数（start/end/granularity/userId）——复用 BE-M1-01 Zod schema，不新造参数语义。
- 实现=调用对应 query 函数（走缓存层）→ 服务端序列化为 CSV，**禁止新写聚合 SQL**（单一口径）。
- CSV 细节：UTF-8 BOM（Excel 兼容）、字段转义（引号/逗号/换行）、表头英文字段名、文件名 `dashboard-<dataset>-<start>-<end>.csv`（Content-Disposition）。
- 限流：按 IP 内存滑动窗口（60s / 10 次），超限 429 `{ ok:false, error:{ code:'rate_limited' } }`；计数器用 lru-cache（max 10k 条防 key 膨胀）。
- `userModels` 数据集必须带 userId（防全库导出）。

## 风险/阻塞
- 限流为进程内计数：多实例部署时各实例独立计数（已知边界，部署卡可评估外部限流）；`x-forwarded-for` 仅在可信反代后可信，直连可伪造（M4 安全收口关注）。
- trend 导出受桶数上限 1000 约束（与页面一致），大区间会 400；CSV 在内存中分批编码（≤1000 行，无流式 DB 游标）。
- 无 PG：demo 行数/数值与 API 一致性未核对（LH-05）。
